② main.py를 6조각으로 읽기



  
1필요한 도구 가져오기

    
주방에 도구를 들이는 단계입니다. FastAPI는 웨이터 훈련 키트, supabase는 창고와 통화하는 전화기입니다.

    
from fastapi import FastAPI
from supabase import create_client


  
2비밀 쪽지(.env) 읽기

    
.env는 창고 주소와 열쇠가 적힌 쪽지입니다. 코드에 직접 쓰면 유출되니 따로 보관하고, .gitignore가 GitHub에 올라가지 않게 막아 줍니다.

    
SUPABASE_URL = os.environ["SUPABASE_URL"]
SUPABASE_SECRET_KEY = ...


  
3창고와 전화 연결

    
쪽지의 주소와 열쇠로 창고에 전화를 겁니다. 아까 Invalid URL 오류는 이 줄에서 주소가 잘못돼서 났습니다.

    
sb = create_client(URL, KEY)


  
4출입 허가 명단(CORS)

    
브라우저는 허가받지 않은 주소의 요청을 막습니다. FRONT_ORIGINS는 "이 손님들은 들여보내 주세요" 명단입니다. 여기에 화면 주소가 없으면 브라우저에서 막힙니다.

    
allow_origins=FRONT_ORIGINS


  
5메뉴판(주소별 할 일)

    
주소마다 웨이터가 할 일이 정해져 있습니다.

    
GET    /health        → 살아있음?
GET    /health/db     → 창고 연결됨?
GET    /notes         → 메모 목록
POST   /notes         → 메모 저장
DELETE /notes/{id}    → 메모 삭제


  
6주문서 양식 검사

    
빈 메모나 너무 긴 메모는 웨이터가 창고에 가기 전에 돌려보냅니다.

    
class NoteIn(BaseModel):
    content: str  # 1~500자





③ 자주 헷갈리는 말





  
말쉬운 뜻

  
127.0.0.1"나 자신"을 뜻하는 주소입니다(= localhost). 인터넷이 아니라 내 컴퓨터 안에서만 통하는 주소입니다.

  
포트 8000한 건물(내 컴퓨터) 안의 방 번호입니다. 웨이터는 8000번 방, 화면은 3000번 방에 있습니다.

  
uvicornmain.py를 켜 놓는 "가게 문 여는" 프로그램입니다. 이 터미널이 켜져 있어야 서버가 살아 있습니다. 창을 닫으면 서버도 꺼집니다.

  
Railway나중에 main.py를 24시간 켜 둘 인터넷 위의 컴퓨터를 빌려 주는 곳입니다. 지금 로컬 테스트에서는 쓰이지 않습니다.

  
Vercel나중에 화면(frontend)을 인터넷에 올려 주는 곳입니다. 이것도 지금은 쓰이지 않습니다.

  
Supabase데이터를 저장하는 창고입니다. 로컬 테스트 때도 인터넷에 있는 진짜 창고를 씁니다.

  
.env주소·열쇠 같은 비밀을 적어 두는 쪽지 파일입니다. 절대 GitHub에 올리거나 남에게 보내면 안 됩니다.




정리: 지금 내 컴퓨터에서는 터미널 2개가 켜져 있어야 합니다.

터미널 1 = 웨이터(uvicorn, 8000번 방), 터미널 2 = 손님 화면(http.server, 3000번 방).

Railway는 말씀하신 "127.0.0.1:8000 서버"가 아니라, 같은 코드를 인터넷에 옮겨 켜는 곳입니다. 그래서 위의 "나중" 모드로 바꾸면 위치만 달라지고 흐름은 똑같습니다.
